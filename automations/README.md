# Automations

Importable n8n workflows. Every file here is a complete workflow JSON: open n8n, go to
**Workflows → ⋯ → Import from File**, pick the file, then attach credentials node by node.

No workflow in this directory contains a credential. That is deliberate — see
[`../SECURITY.md`](../SECURITY.md).

## Groups

| Folder | Holds | Example |
|---|---|---|
| `ai/` | Agent, chain, RAG and LLM workflows | `agents_vs_chains.json` |
| `integrations/<app>/` | Workflows built around one app | `integrations/googledrive/get-most-recent-file.json` |

| `patterns/` | Cross-cutting patterns and tutorials | `patterns/tutorial.json` |
| `_template/` | Starting point for a new automation | — |

## Adding a workflow

Step 1: copy the template folder.

```bash
cp -r automations/_template automations/integrations/my-service
```

Step 2: export from n8n (**Download**, not a hand-written file) and replace `workflow.json`.

Step 3: scrub it. Remove API keys, tokens, sheet ids, folder ids, instance ids, personal
emails, and any webhook path segment that acts as a secret.

Step 4: write the automation README — what it does, what triggers it, which credentials it
needs, what it assumes.

Step 5: validate.

```bash
python3 tools/validate_repo.py
```

Step 6: commit.

```
feat(automations): add Gmail-to-Sheets invoice logger
```

## Conventions

- **File names** describe the job (`invoice-logger.json`), not the node (`http-request.json`).
- **Node names** are unique and readable. `connections` is keyed by name; duplicates merge
  silently and produce a workflow that looks fine and runs wrong.
- **`type`** must be a real node type — the `workflow_type` field in the knowledge base.
- **`typeVersion`** is mandatory. Omitting it makes n8n fall back to defaults that may not
  match the parameter names you used.
- **Positions** flow left to right, 220 px apart, with 150–200 px between branches. AI
  sub-nodes sit below their agent.
- **Sticky notes** carry intent and the credential checklist for anything non-obvious.
- **Error handling**: production workflows should set a workflow-level error workflow, not
  rely on the default.

## registry.json

Generated by `tools/validate_repo.py`. For each workflow it records:

| Field | Meaning |
|---|---|
| `file` | Path relative to the repository root |
| `name` | Workflow `name` |
| `node_count` | Number of nodes |
| `node_types` | Every node type used, so you can see what must be installed |
| `trigger` | The trigger node type, if one exists |
| `kb_records` | Knowledge-base records for the built-in nodes used |
| `community_nodes` | Non-built-in node types — these need a community package |
| `sha256` | Content hash, so a silent edit is visible |

Never hand-edit it. Regenerate and commit.
